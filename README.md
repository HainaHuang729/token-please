# Token, Please!

**请出示你的上游。** 一款模型中转站验收游戏。

[在线试玩](https://hainahuang729.github.io/token-please/) · [English](README.en.md)

基于 [IP, PLEASE](https://github.com/ip-please/ip-please.github.io) 的中文同人五章节游戏，保留十个参考形象角色。玩家验收模型服务，检查订单是否与可信上游回执一致。模型名、角色外表和口头自称不是证据。订单、签名、计价与服务数据均为虚构剧情，不调用真实模型接口。

## 运行和玩法

双击 `index.html`，或运行 `python3 -m http.server 8766` 并访问 http://localhost:8766 。

1. 点击左下「接单」，把订单拖到桌上。
2. 点击「调取回执」或按 R，等待上游回执打印。每单必须核验。
3. 核对编号、签名、授权模型、输入转发量和扣款。右下「比对」可点选订单和回执字段，发现问题后询问。
4. 符合合同盖绿色「验收通过」；交付不符盖红色「退回整改」。
5. 伪造回执、未授权跨品牌替换必须先点「标记欺诈」，再盖退回章。误标和漏标均扣分。同品牌降级、缩水与超收只需整改。
6. 把盖章订单拖回左侧，接下一单。每章结算后进入下一章，五章完成后可重新开始。

F 全屏，M 静音。标题页「查看交付方档案」查看十角色。当前没有中途存档。

## 章节

| 章节 | 订单数 | 新内容与新角色 |
|---|---:|---|
| 第一班岗 | 4 | 原装与套牌；GPT、DeepSeek、Claude |
| 同名不同款 | 5 | 同品牌降级；Gemini、GLM |
| 合法的代班 | 6 | 授权代工、自建；Qwen、Meta |
| 少传与多收 | 7 | 输入截断、超收；Kimi、MiniMax |
| 最后一跳 | 8 | 协作步骤与顺序、假回执；Grok |

旧规则持续生效；人物重复出场，修正订单或带来不同授权，不能用角色身份推断结果。章节内容和规则由 `chapters.js` 管理。

## 基础案件模板

| 角色 | 案件 | 处理 |
|---|---|---|
| GPT | 型号、输入转发量、扣款与订单一致 | 通过 |
| DeepSeek | 订单只允许 Claude，后台未经授权由 DeepSeek 代工 | 标记欺诈并退回 |
| GLM | 旗舰被换成轻量版，未获降级同意 | 退回整改 |
| Gemini | 原装交付、资料完整 | 通过 |
| Qwen | GPT 订单明确允许路由到 Qwen，按实际低价结算 | 通过 |
| Grok | 回执编号不符且签名无效 | 标记欺诈并退回 |
| Meta | 订单披露并允许自建服务 | 通过 |
| Kimi | 承诺 128K，仅交付 32K | 退回整改 |
| MiniMax | 预算 4 token，扣款 9 token | 退回整改 |
| Claude | 授权 Qwen 检索、DeepSeek 起草、Claude 审核的流水线 | 通过 |

首个错误仅警告，之后每错扣 5 token；每单正确验收工资 5 token。每章首错提醒独立计算，全程共 30 单，结算显示累计正确数。

## 实现

`relay-cases.js` 保存结构化合同与回执。`relayVerdict()` 根据授权范围、签名、输入转发量、协作顺序和预算计算处理结果，区分未授权跨品牌替换与同品牌降级。`relaySpec()` 生成订单、回执、字段比对关系和对话。

`nightshift.js` 负责验收场景、回执请求、欺诈标记、标题、图鉴和结算。核验在回执打印后生效，不能连续重复请求。`booth.js`、`docs.js` 和 `tools/pp/docs.py` 的按钮、规则书与印章已改为验收语境。

本地 `pixel-art/ai-cast/animations/` 保存十位角色各自的 3×2 生成连环图、六张裁切帧、对齐记录和 GIF 预览。`manifest.json` 保留生成提示词。`tools/prepare_portrait_animation.py` 按固定网格裁切，共用缩放比例并对齐，固定非脸部底图；眼睑和嘴型使用生成图里的真实表情像素，不再用色块遮盖。`tools/build_assets.py` 将 60 帧嵌入图集。原生内容为 124×124，最近邻显示；眨眼依次播放半闭、全闭、半睁，说话播放两档口型，并保留一像素呼吸。减少动态效果模式保持静止，戴面具时面具保持刚性。原始 `all-models-neutral.png` 和 `all-models-talk.png` 作为参考与兼容底图保留。

## 控制台界面

雾蓝工作区与深蓝通讯窗口，青色标识订单、紫色标识回执，红色留给欺诈与退回。顶部显示本章队列及当前进度。新增值班交接说明与下一步提示。使用原像素字体，与角色图集保持清晰的像素边缘。手机推荐横屏，竖屏保留提示与继续入口。`test-console-ui.mjs` 验证横屏触控接单/调回执及竖屏引导。

`ui-polish.js` 统一章节进度、队列状态、操作阶段和打印/盖章反馈。新增过渡使用游戏时钟，支持系统减少动态效果；按钮与文件命中区域保持原位。运行 `node test-ui-motion.mjs` 检查普通与减少动态效果模式，`node test-console-ui.mjs` 检查手机触控。

`relay-banter.js` 保存五章 30 单的独立出场/核验台词、角色通过与退回反应，以及章节交接段子；只修改叙事，不修改证据和判定。`node test-banter.mjs` 检查台词宽度、独立出场文案和实际显示。

`relay-challenges.js` 增加后期细微差异：有效签名配错编号、型号后缀、少量输入截断、小额超收和复合错误。五章违规单数为 1/3/4/5/6（共 19/30）；第一章保留教学提示，其后核验不自动透露解释，需比对后询问。签名有效但编号不符仅退回，不能因此误标伪造签名。`node test-challenges.mjs` 检查边界、字段比对、十角色帧稳定和不自动招供。原基础案件表只表示模板，具体章节以挑战数据为准。

`relay-masks.js` 为七次出场配置另一模型的纸质面具，使用 `model-masks-v2.png` 独立生成的贴脸面具素材，按角色脸部坐标绘制面具与细绑带，保留本人的身体与头发；队列同步显示。面具不参与判定，授权订单仍可通过。运行 `node test-masks.mjs` 检查全部面具、说话稳定性和同装扮不同授权结果。

`portrait-motion.js` 定义十位角色的脸部位置与局部动作。`node test-portrait-motion.mjs` 验证眨眼/口型不会改动身体区域、呼吸位移及减少动态效果行为。

本地界面比较：顶部可切换复古终端、纸质审单台、调度控制室三版；`?design=terminal`、`?design=paper`、`?design=dispatch` 可直接选定。切换只改变绘制，不重置订单和材料位置。`ui-variants.js` 集中维护三版外观，`test-ui-variants.mjs` 覆盖三版拖单、核验、盖章、归还与持久化。面具直接取当前 GPT / Claude 原头像的脸部并绘制绑带、边缘，保持身份一致。

正式站点默认采用复古终端 UI；设计切换栏仅在本地或带 `?design=` 的预览地址显示。

公开仓库包含运行和重建图集所需的六帧裁切图；高分辨率原图、中间裁切图和 GIF 工作预览保留在本地备份分支 `codex/source-art-1.2.0`。
